# Deploying EventPass

Everything runs on free tiers:

| Part | Where | Why |
| --- | --- | --- |
| PostgreSQL | [Neon](https://neon.tech) | Free Postgres that doesn't expire (Render's free database is deleted after 30 days) |
| API | [Render](https://render.com) web service, from [`render.yaml`](../render.yaml) | Builds from GitHub on every backend push, runs migrations on start |
| Demo data | GitHub Actions ([`demo-reseed.yml`](../.github/workflows/demo-reseed.yml)) | Re-creates the demo events every 6 hours so there is always a live event |

Free Render services sleep after 15 minutes without traffic. The first request after that takes up to a minute while the service wakes up; later ones are fast.

## 1. Database (Neon)

1. Sign up at neon.tech and create a project named `eventpass`, region **AWS Asia Pacific (Singapore)** (the API runs in Singapore too).
2. **Connect** → copy the connection string. It looks like
   `postgresql://neondb_owner:…@ep-….ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.

## 2. Secrets

Generate the key that encrypts each event's private signing key:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

Keep it somewhere safe (a password manager). If it's lost or changed, existing events can no longer issue tickets.

## 3. API (Render)

1. Sign up at render.com with GitHub and allow access to the `eventpass` repository.
2. **New → Blueprint** → pick the repository. Render reads `render.yaml` and asks for:
   - `DATABASE_URL`: the Neon connection string
   - `KEY_ENCRYPTION_KEY`: the key from step 2
   
   `JWT_SECRET` is generated by Render.
3. **Apply**. The first build takes a few minutes. Then open
   `https://eventpass-api.onrender.com/health` (your URL is on the service page); it should return `{"status":"ok"}`.

The tables are created on start (`npm run start:prod` runs the migrations first).

## 4. Demo data (GitHub Actions)

1. GitHub repo → **Settings → Secrets and variables → Actions → New repository secret**:
   - `DEMO_DATABASE_URL`: the Neon connection string
   - `DEMO_KEY_ENCRYPTION_KEY`: the same key as on Render
2. **Actions → demo-reseed → Run workflow** to seed now. After that it runs every 6 hours.

Demo accounts (password `eventpass-demo`): `organizer@eventpass.dev`, `staff@eventpass.dev`, `attendee@eventpass.dev`.

## 5. Point the clients at the API

- **Admin dashboard:** set `VITE_API_URL` to the Render URL when deploying it, then set `CORS_ORIGIN` on Render to the dashboard's URL.
- **Mobile app:** `flutter build apk --release --dart-define=API_BASE_URL=https://eventpass-api.onrender.com`.
